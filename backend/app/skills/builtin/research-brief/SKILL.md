# 资料简报

把从知识库查到的资料整理成一份 Markdown 简报，写进工作区。负责制作文件的成员会直接读这份文件，所以简报就是它们唯一的资料依据。

路径里的尖括号是占位符，写成绝对路径：`<工作区>` 的实际位置见系统提示「文件放哪」那节。

## 步骤

1. 查知识库，按下面三条控制次数：
   - 先用 2–3 个宽泛的关键词查（如产品名、「功能」「客户」），一次查询覆盖多节，不要一节一查。
   - 某一节换过两次关键词仍查不到，就当作资料里没有，写进「资料中没有的内容」，不再查它。
   - 全部查询控制在 6 次以内；能同时发出的查询在同一次回复里一起发。
2. 按下面的格式写成 `<工作区>/资料简报.md`（用 `write_file`）。同一轮已经有这个文件时，先读出来，在原文件上补充，不要另起一份。
3. 回复只写一句：简报已写好、路径是什么、哪些节资料不足。**不要把简报正文贴回对话。**

## 格式

```markdown
# 资料简报：<主题>

## 产品定位
一两句话：是什么、给谁用、解决什么问题。〔出处：<资料名>〕

## 目标客户
- 客户类型与典型角色〔出处〕

## 核心功能
- **功能名**：做什么、带来什么效果〔出处〕

## 典型场景与案例
- 场景 / 客户：怎么用、结果如何〔出处〕

## 关键数据
- 数字 + 单位 + 口径说明〔出处〕

## 资料中没有的内容
- 任务需要、但知识库里查不到的信息
```

## 要求

- 每条都要标出处（知识库里的资料名或标题）。
- 只写资料里有的内容；查不到的写进「资料中没有的内容」，**不要推测、不要编造**数字和案例。
- 原文过长时提炼要点，保留数字、名称和专有说法，不改写成别的意思。
- 用户在任务里提到的客户行业、篇幅、侧重点，写在简报开头一行「本次要求：……」，制作成员会照着做。
