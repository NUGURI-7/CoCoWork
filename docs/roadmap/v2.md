## P0 · 含金量主攻(简历核心,先做)

### 1. 多 Agent 上下文工程

Isolate ✅ 早在 V1 就有(视角化 + subagent 隔离),另三块的结局各不相同:

- ✅ **回放保真**(2026-07-14 + 07-31 两轮) — 原不在计划内,是实测翻车逼出来的。按块翻译管线 + 跨轮回放协议改造(历史里放回结构化 `tool_calls`/`ToolMessage`,修掉 supervisor 空手编造派活)。**这是 Compress 层 B 的地基**。
- ✅ **Compress 层 A**(2026-07-20) — 单次 run 内的膨胀保险丝,deepagents `SummarizationMiddleware` + adapter 泄漏过滤。
- 🚧 **Compress 层 B**(进行中) — 跨轮历史压缩。切片 1-2 已落(`ConversationSummary` 表 + 迁移 0015 + usage 记账),剩压缩 service / assembler 接线 / 测量(token 曲线 + cache 命中率)。已定调:封存边界 + 摘要落独立表跨轮复用护 cache + 中性摘要一份 + 近 N 轮照旧视角化 + 阈值取 API usage。
- ❌ **Select**(@直连成员按相关性取历史,不喂全量) — **与 Compress 的设计前提直接冲突**:Select 按 query 挑,每轮挑出来的不一样 → prompt 前缀每轮都变 → prompt cache 全丢;而层 B 整套设计(摘要文字定死、落表跨轮复用)就是为护 cache 而定的(实测 DeepSeek 同前缀 98% 命中)。两者只能取一,取 Compress。
- ❌ **Write**(workspace 级共享内存「白板」) — 原始诉求「成员产出互不可见、多 Agent 互相失忆」**已被沙箱产物系统覆盖**:`sandbox_artifacts` 表 + `fetch_artifact` 按需取回 + 右栏跨对话面板 + 拖回输入框。形态是文件不是内存,解的是同一个问题。`WorkspaceContextMiddleware` 空壳代码保留当接缝,但不再挂 backlog。
- 参考:Anthropic《多 Agent 研究系统》/《Effective context engineering》、Cognition《Don't Build Multi-Agents》、LangChain Context Engineering

### 2. RAG 进阶

从"向量检索"到"工业级检索"。**本块已收官**,且收官方式是三个**否决式结论** —— 尺子(评测设施)本身反而成了最大产出:

- ✅ **混合检索**:Postgres 原生 FTS(tsvector + GIN + jieba + 停用词,07-18)+ 加权 RRF 融合(07-19)全部实装。**但产品默认回退纯向量** —— 双域四组实验判出局:电商域 keyword 腿强了近三倍、hybrid 增益反而归零,机制是**价值在互补性不在腿强度**。翻案唯一路径 = 真 BM25(本地 ES 单容器)后重考,pg_search 已否决。
- ✅ **Rerank**(07-20,首发硅基流动 bge-reranker-v2-m3;"先阿里"因 gte-rerank 下线改道):Model 模块接入 + 检索管线两级化 + KB 库级检索设置全栈。**结论同样是域依赖** —— 医疗 +2.5pt recall,电商 −2.8pt:**向量吃干净的域,加什么都是噪音**。
- ✅ **评估体系**:Multi-CPR 医疗域 96 万 passage + ranx 算 recall@10 / MRR@10 + 结果自动存档;实验发现录 `backend/benchmarks/FINDINGS.md`(六轮实验的量化结论全在里面)。顺带产出 **HNSW 实战:服务端 p50 237ms → 11.8ms、召回无损**,以及"建完索引不被用"的两个凶手(SQL 形状 / 规划器成本误估)。
- ✅ **切块优化**(2026-07-29 收官,`docs/design/pdf-parsing-v1.md` 五步全部完成)—— **2026-07-31 核对更正**:本条一度被误记为待办。实际已落地:标题感知分段(兑现 v1 遗留缺陷 —— 双换行段对 list-heavy md 失效、一整天行程挤成一巨段)、`Parser` ABC + txt/markdown/PDF 三实现、pdfplumber 本地路 + 百度云 API 云端路两条解析路(库级 `parse_backend` 枚举分发 + 云端失败降级本地)、定位信息(标题链 + PDF 页码)落 `Paragraph.meta` 并透到检索结果。
- ⏳ **子块拼标题** — **本块唯一还欠的**:标题链已经算出来并存进 `Paragraph.title` 了(`assembler.py`),但 `document_processor` 切块时只把 `paragraph.content` 喂给 splitter,**标题链没有拼进送去 embedding 的文本**。改动极小,且收益能用现成的尺子(ranx recall@10 / MRR)直接量化。
- ❌ **多向量**(question / title 双向量)— 已砍。
- 挂账(永久,无期限):ES / 自定义词库 / Milvus 可插拔、生成端评测(自己写,不装 RAGAS)。

选型从 ARQ 改为 **SAQ 0.26.4**。

- ✅ 队列 + 独立 worker 进程(`app/tasks/`:queue 单例 / worker 配置 / `app/cli.py` 双入口 `uv run dev` `uv run worker`)
- ✅ 文档处理管线从 `BackgroundTasks` 迁过来(07-23),`tasks/` 三层定型:registry 契约 / `*_task.py` 实现 / worker 进程

## 已知欠账(不属于任何 P,但迟早要还)

- **`AIModel.meta` 模型能力标记** —— 字段建了但恒为 `None`。缺它就没法「按模型一格一格开」:是不是推理模型(决定 `max_tokens` 预算、能否关思考)、context window、上不上报 cache。07-31 起名踩坑(推理模型把 128 token 全吃光、输出为空)就是它缺位的直接后果。**不能退到 `param_adapter` 层解决** —— 那层的 key 是 LC provider 家族(`openai` 一格罩着 DeepSeek / 通义 / SiliconFlow / custom 全部),加进去等于对所有兼容端点盲传。
- ~~`timeAgo` 前端三份拷贝待收敛~~ ✅ 2026-07-31 已还(实为**四**份)。收敛方式不是抽公共函数,而是**统一到项目早已装好的 dayjs `fromNow()`** —— `main.tsx` 里 `relativeTime` 插件 + `zh-cn` locale 一直配着、`DocumentList` 也一直在用,等于标准方案就在手边而那四处各自手写。顺带除掉手写版的 `Math.max(m, 1)`:它会把负数差值(时间戳跑到未来 = 数据出错)一律兜成「1 分钟前」,**正是 07-31 那个时区 bug 藏了这么久的原因**。
