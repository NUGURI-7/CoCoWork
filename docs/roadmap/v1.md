# CoCoWork V1 — 功能详档

> 状态:**已封板(2026-06-20)** · 路线总览见 [README](./README.md)
> 定位:跑通「多 Agent 编排 + RAG 检索」核心闭环的可演示版本。
> 技术栈:FastAPI · Tortoise ORM · PostgreSQL(pgvector)· Redis · LangGraph / deepagents · React 19 · TanStack Router · shadcn/ui
> 阅读约定:**功能清单** = 已实现、用户可用的能力(产品视角);**后端关键设计** = 底层技术亮点;前端从简。

---

## 1. 平台底座(基础设施)

支撑所有业务的通用地基。

**功能清单**
- 后端服务可启动:FastAPI 接 Tortoise(PostgreSQL)+ Redis,全生命周期就绪
- 生产级日志:开发彩色 / 生产 JSON 自动切换,每条带请求 id(`[req-xxx]`)做链路追踪
- 统一异常体系 + 中间件,错误响应结构化
- 文件存储:支持 Cloudflare R2(预签名直传 / 下载)与本地磁盘两种后端,配置一键切换
- 内置管理员账号启动自动创建,免手动初始化

**后端关键设计**
- 存储层 `Storage` ABC + R2 / Local 双实现 + 按配置装配的模块级单例;同步 IO 全包 `asyncio.to_thread`,boto3 懒加载
- Local 后端路径穿越防护;上传后 `stat_size` 复校真实大小,超限自动清理

## 2. User / 认证

账号注册、登录与身份识别。

**功能清单**
- 用户注册 / 登录 / 获取当前登录用户
- 密码安全存储,登录后签发 token
- 区分普通用户与管理员

**后端关键设计**
- JWT + argon2 哈希;`get_current_user` 每请求查库 + 校验 `is_active`
- 内置 admin 启动 seed(`is_admin=True`)

---

## 3. Model — 模型接入管理

接入并管理各家大模型供应商与模型实例。

**功能清单**
- 供应商(Provider)管理:创建 / 列表 / 详情 / 更新 / 删除,凭据加密保存
- 模型实例(AIModel)管理:在某 Provider 下增删改查;可覆盖 Provider 的 base_url / api_key
- 创建 / 更新时**自动校验连通性**(按供应商类型 + 模型类型选对应校验策略)
- 跨供应商查询自己的所有模型(按类型 / 启用状态过滤)
- 管理员维护「可用模型目录」,普通用户配置时从目录里选
- 模型参数动态表单(后端吐参数定义,前端按定义渲染)

**后端关键设计**
- 三层数据模型:Provider(凭据)+ AIModel(实例)+ ProviderModelCatalog(管理员目录)
- API Key 走 Fernet 加密存储
- Validator 策略模式:`provider_type × model_type` 二维查找校验器
- 统一 OpenAI 兼容客户端(ModelClient)

---

## 4. Knowledge / RAG — 知识库与检索

建库、传文档、自动向量化、语义检索(V1 = 向量检索)。

**功能清单**
- 知识库:创建 / 列表 / 详情 / 更新 / 删除;每库锁定一个 embedding 模型
- 文档上传:大文件直传(R2 预签名)/ 后端中转(本地),带真实上传进度
- 文档管理:列表 / 分页 / 详情 / 删除 / 下载;批量向量化 / 批量删除(部分成功语义)
- 自动处理管线:解析 → 切块 → 批量 embedding,状态机推进(待处理 / 处理中 / 就绪 / 失败),失败可重试
- 命中测试:输入 query 做语义检索,返回命中段落 + 相关度分,直接在库内调检索效果
- 知识库可被 Agent 关联,成为 RAG 外挂(见 Agent 模块)

**后端关键设计**
- pgvector 0.8.1 + VectorField;检索走原生 SQL 余弦距离 + `DISTINCT ON` 按段去重 + 阈值过滤 + top_k,全参数化防注入
- Splitter 抽象层(包 langchain `RecursiveCharacterTextSplitter`,可 swap 自研对照)
- 父子块:命中返整段 content + 命中子块 chunk_text + score(= 1 − 距离)
- 处理管线重入清旧段落(FK CASCADE 连带清 embeddings)
- 限制:扩展名 md / txt,单文件 ≤ 50MB

---

## 5. Agent — AI 助手的创建与调试

让用户创建、配置、调试自己的 AI 助手。

**功能清单**
- 从模板创建 Agent(当前:1 个通用对话引擎)
- 配置:对话模型 · 角色设定(system prompt)· 内置工具 · 关联知识库
- 改动有「未保存」提示 + 一键保存
- Playground 沙盒:配置页内即时调试对话(流式输出 + 随时停止,不留记录)
- 我的 Agent 列表:创建 / 删除
- 真实工具调用:LLM 会算数(计算器)、会查关联知识库并引用结果

**后端关键设计**
- Hybrid Schema:固定列 + `config` jsonb(强类型校验,`extra="forbid"` 禁脏字段)
- 模板层 1+N:1 个可配置 loop 引擎 + N 个图模板,装饰器注册表装配
- 工具装配单点 `_assemble_tools`:内置工具与知识库走**同一入口**接进 Agent
- runtime 解耦:`AgentSpec` frozen dataclass 作对话内核契约,Playground 与 Workspace 复用零改动

---

## 6. Tool — 工具能力

给 Agent 装上可调用的工具(V1 = 内置工具第一刀)。

**功能清单**
- 工具列表:列出当前可用工具(名称 / 显示名 / 描述 / 来源 / 危险标记)
- 内置计算器:LLM 可调用做精确数学运算
- 知识库作为工具:关联的 KB 自动包装成检索工具供 LLM 调用(Agentic RAG)

**后端关键设计**
- `CoCoTool` 基类:模板方法统一兜 cap / timeout / 异常 + 元信息(display_name / source_type / dangerous)
- 注册表启动期 name 正则 fail-fast;calculator 用 AST 白名单求值(零依赖、防注入、防 CPU 炸弹)
- 工具按来源分字段(`builtin_tools` 等),`_assemble_tools` 单装配点扩来源不动调用方
- KB 检索工具:per-KB bound 实例,只暴露 `query` 给 LLM(同 LangChain `create_retriever_tool` 范式)

> 前端 `/tools` 展示页为静态骨架;MCP / 自定义工具属 V2。

## 7. Workspace — 多 Agent 协作空间

把多个 Agent 招进一个空间,由内置管家(Supervisor)统一协调对话与派活。

**功能清单**
- 工作空间:创建(自带管家 + 初始对话)/ 列表 / 详情 / 更新 / 删除
- 成员管理:从「我的 Agent」招募成员(不可重复招募)/ 通讯录列表 / 移除成员
- 多对话:一个空间下多个会话,创建 / 切换 / 重命名 / 删除,历史回放
- 管家对话:跟内置管家流式对话并落库持久化(done / error / stopped 三态)
- @直连成员:输入框 @ 某成员,让它绕过管家直接应答
- 派活协作:管家自动把任务分派给招募成员,子任务执行过程实时折叠展示
- 群聊式界面:管家 / 成员 / 用户身份区分,各显头像与名字(实时 + 回放一致)
- 多会话并发:切到别的对话后,原对话的流在后台继续跑完并落库,切回接着看;对话状态点(进行中 / 出错)实时显示
- 右栏:空间配置 ⇄ 产出物 翻转面板

**后端关键设计**
- 架构(方案 C):外层 StateGraph + 内置 Supervisor(存 `workspace.supervisor` jsonb,不进 agents 表)
- 成员 = 对 Agent 的不可变硬 FK 引用,`unique(workspace, agent)` 防重复招募
- 消息三层身份:`role`(user / assistant)+ `sender_kind`(user / supervisor / member)+ `sender_member_id`(踢人保历史)
- 派活:deepagents `SubAgentMiddleware`,每成员转 `CompiledSubAgent`,子 agent 独立上下文(只收一句话任务)
- 视角化上下文:`ViewContextAssembler` 按应答者视角重写历史(自己 → AIMessage,他人 → 带 `<msg from>` 标签的 HumanMessage),prompt cache 友好
- 对话流事件总线化:adapter 吐 `(EventType, payload)`,runner sink 旁路一份落库一份给前端(tee)
- `thread_id = conversation.id.hex` 映射 LangGraph checkpointer

**前端关键点**(从简)
- 通用对话层 Playground / Workspace 复用(chat-store 工厂 + SSE 解析 + 智能滚动 + 真停止)
- 多会话并发靠模块级 `chat-registry`(`Map<conversationId, store>`)把 store 移出组件生命周期 + `stream-status` 状态表
- @mention 输入用 TipTap(atomic token,id 挂 node + floating-ui 候选浮层)

## 8. 前端 App Shell / Admin(从简)

**功能清单**
- 登录 / 注册页(双栏品牌风)
- 工作台 App Shell:可收起 sidebar(主页 / Agents / 知识库 / 工具 / 模型)+ 头像菜单(设置 / 退出)
- 个人主页 dashboard(卡片式,静态占位待灌真数)
- Admin 独立后台:`/admin` 分区(isAdmin 守卫)+ 系统设置(模型目录管理,管理员增删)+ 用户管理(前端 mock,后端属 V2)
- 全局:路由 → tab 自动同步;品牌色「适度品牌化」色阶 token 体系
