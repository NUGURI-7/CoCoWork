# CoCoWork 核心能力

## 一、业务 Agent：一件具体工作，一个专用能力

每个业务 Agent 对应一项具体工作，写明需要员工提交什么、最终交付什么。例如「合同初审」接收合同，返回问题清单、原文位置和修改建议；「门店营销音频」接收活动需求，交付可直接在门店播放的音频。

- **流程由开发侧定义**：检查步骤、依据来源、交付格式都封装在业务模板里，员工不需要写提示词。
- **两项可配置**：管理员只需选择对话模型、绑定知识库。同一个业务模板可以建多个 Agent，例如不同门店各自绑定自己的资料库。
- **启用即上线**：Agent 启用后全员可见，停用后员工看不到，历史会话保留。修改配置保存即生效。
- **公共与个人**：管理员用业务模板创建的公共 Agent 全员可用；员工也可以用通用模板为自己搭建问答、检索类的个人助手。

**适用情况**：边界清楚、输入和交付都能说清的一件工作，例如审一份合同、写一段播报、回答一类制度问题。

**两种流程形态**：

| 形态 | 特点 | 适合的工作 |
| --- | --- | --- |
| 固定流程 | 步骤、依据和确认节点写在代码里，每次必走 | 合同初审、单据核对等按清单检查的工作 |
| 灵活执行 | Agent 按任务自行决定查什么、用什么工具 | 内容创作、资料问答等每次要求都不同的工作 |

两种形态可以组合：固定流程中的某一步交给 Agent 灵活处理，例如营销音频先由 Agent 查资料写稿，再进入固定的确认与制作环节。

## 二、多 Agent 协作工作空间

一项任务需要多种能力时，可以交给工作空间。工作空间里有一位 Supervisor（调度者）和若干成员 Agent：

- **自动拆解与分派**：员工只说要什么，Supervisor 把任务拆成若干子任务，分派给合适的成员；互不依赖的子任务同时执行。
- **过程可见**：分派给了谁、每位成员进行到哪一步，都在对话中实时呈现。
- **指定成员应答**：用 @ 可以直接找某位成员，跳过调度；成员清楚自己的身份、前面的对话和分给自己的任务。
- **上下文隔离**：每位成员只看到与自己任务相关的信息，资料查询中的大量原文不会干扰制作成员。
- **预设与自由搭配**：员工可以直接进入配好的工作空间，也可以从现有业务 Agent 中挑选成员组合。
- **成员之间通过文件交接**：前一位成员把整理好的资料写成文件，后面的成员直接读取同一份文件，避免信息在多次转述中走样。

**适用情况**：一项任务需要多种能力配合，或者可以拆成几件互不依赖、能同时进行的工作，例如同时制作 PPT、Word 和 PDF。

**使用建议**：边界清楚的单件工作直接用单个业务 Agent 更快；只有确实需要分工时才用工作空间，因为调度和交接本身也需要时间。

## 三、知识库检索

- **多种格式**：支持 PDF、Markdown、文本等文档，自动解析、按语义切分，PDF 保留标题结构和页码位置。
- **多种检索方式**：向量语义检索、关键词检索和两者融合的混合检索，并支持重排序进一步提升相关性；每个知识库可单独设置检索方式。
- **Agent 自主检索**：知识库关联到 Agent 后，查哪个库、查几次、换什么关键词，由 Agent 在执行中自行判断。
- **检索效果可测试**：资料维护者可以在页面上直接输入问题，查看命中的段落和得分，及时调整资料。
- **资料维护分工**：部门资料维护者负责上传、更新、删除文档，管理员决定哪个 Agent 绑定哪个库。
- **后台处理**：文档上传后由后台任务完成解析和建立索引，大批量文档不会阻塞页面操作；处理失败的文档会显示原因，可以单独重试。

**检索方式怎么选**：

| 方式 | 擅长 | 适合的资料 |
| --- | --- | --- |
| 语义检索 | 理解同义表达，问法和原文用词不同也能找到 | 产品介绍、制度说明等叙述性文档 |
| 关键词检索 | 精确匹配型号、编号、专有名词 | 产品目录、参数表、编号清单 |
| 混合检索 | 兼顾两者 | 内容类型混杂的资料库 |

**使用建议**：一个知识库放同一类资料、同一个主题，比把所有资料混在一个大库里检索效果更好；文档标题和小标题写清楚主题，有助于定位到正确段落。

## 四、任务执行与产出物

- **真实执行**：涉及计算、绘图、文件生成的任务，Agent 会在隔离的执行环境中实际运行代码并给出结果，而不是只给出建议。
- **专业文档制作**：内置 PPT、Word、PDF 制作技能，按公司品牌模板（Logo、页眉页脚、品牌色、中文字体）生成可编辑文件。
- **产出物面板**：生成的文件统一归集，可以预览、下载，也可以拖回输入框交给其他成员继续加工。
- **基于历史继续修改**：「在昨天那份 PPT 上加两页实施计划」，Agent 会取回历史文件，在原文件上修改并保存新版本。
- **交付前自检**：文档类文件生成后自动做格式校验，检查文件能否被 Office 正常打开、内容是否完整，发现问题先修正再交付。

**支持的产出类型**：PPT 演示文稿、Word 文档、PDF 文件、数据图表（柱状图、折线图、饼图）、MP3 音频。

**技能机制**：文档制作等能力以「技能」的形式提供。一项技能包含操作说明、公司模板、素材和配套脚本，挂到哪位成员身上，哪位成员就具备这项能力。技能的好处在于：

- **企业规范内置**：公司 Logo、页眉页脚、品牌配色、中文字体都写进技能的模板里，生成的每份文件都自动符合规范，不依赖员工或模型记得。
- **单独维护**：PPT、Word、PDF 各是一项独立技能，调整 PPT 模板不会影响另外两种文件。
- **按需装配**：每位成员只挂自己职责需要的技能，不会被无关的说明干扰。

## 五、人工确认

- **关键节点暂停**：遇到需要员工决定的环节，例如确认播报稿、补充缺失信息，流程会停下来，用表单列出待确认事项。
- **确认后继续**：员工修改并提交后，从暂停处继续执行，不会从头再来。
- **关闭页面也不丢失**：页面关闭后重新打开，待确认的表单仍然保留。
- **多种确认方式**：表单支持文本修改、单选、多选和勾选，按钮可以区分「确认」「取消」等不同去向，员工选择取消时流程直接结束，不会执行后续操作。

**典型用法**：生成前确认（音频制作前确认播报稿）、信息不全时追问（缺少活动门店时询问）、高风险操作前确认（执行有副作用的操作前请员工确认）。

## 六、长期记忆

员工明确提出的偏好和固定要求（例如「汇报材料一律用正式语气」「数字保留两位小数」）会被记录下来，在新的会话和工作空间中自动生效，不必每次重复交代。

## 七、平台治理

- **体验与用量限额**：可按场景限制调用次数，控制模型成本。
- **消耗明细**：每次回复记录各环节的模型调用消耗，Supervisor 与每位成员分开统计。
- **模型统一接入**：管理员在后台接入模型供应商，支持兼容 OpenAI 协议的主流模型服务，员工无需了解模型细节。
