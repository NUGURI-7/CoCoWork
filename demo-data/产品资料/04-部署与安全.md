# CoCoWork 部署与安全

## 部署形态

- **私有化部署**：整套系统以容器方式交付，部署在企业自己的服务器或私有云上，业务数据和知识库不离开企业环境。
- **组件构成**：应用服务、后台任务服务、代码执行沙箱服务、PostgreSQL（含向量检索扩展）、Redis，以及兼容 S3 协议的对象存储。
- **起步门槛低**：单台服务器即可完成部署，用 Docker Compose 一键启动；随着使用规模扩大，可以把各组件拆分到多台服务器。
- **后台任务独立运行**：文档解析、建立索引、音频制作等耗时任务由独立的后台任务服务执行，不影响员工的对话响应。

## 模型接入

- **统一接入**：管理员在后台添加模型供应商，系统自动验证连通性。支持兼容 OpenAI 协议的主流模型服务，包括国内主流大模型平台和企业自行部署的开源模型。
- **按能力分别配置**：对话模型、向量模型、重排序模型分别管理，每个业务 Agent 可以选用不同的对话模型，兼顾效果和成本。
- **员工无感知**：员工使用业务能力时不需要选择模型，更换模型只需管理员在后台修改配置。

## 权限与可见范围

- **公共 Agent 与个人 Agent**：管理员用业务模板创建的公共 Agent 全员可用、只有管理员能修改；员工用通用模板创建的个人 Agent 只有本人可见。
- **启用与停用**：Agent 停用后对员工不可见，历史会话保留，便于下线和问题排查。
- **知识库分工**：资料维护者维护本部门的文档，管理员决定 Agent 绑定哪个知识库；Agent 运行时只加载员工有权使用的知识库、技能和工具。
- **任务材料不进知识库**：员工为单次任务提交的材料随对话保存，不会混入共享知识库。

## 一次任务中的数据流向

以「查资料并制作文档」为例，说明数据在系统中如何流转：

1. 员工的需求和提交的材料随对话保存到企业自己的数据库，只有本人和有权限的人可以查看。
2. Supervisor 和成员调用对话模型时，发送的是完成当前任务所需的内容：需求、检索到的相关段落、任务说明，而不是整个知识库。
3. 知识库检索在企业数据库内完成，只把命中的段落交给模型。
4. 文件制作在沙箱容器中进行，生成的文件写入交付区后上传到企业的对象存储，容器随后销毁。
5. 员工在产出物面板中下载文件，文件访问需要登录身份校验。

如果选用企业内部部署的模型，第 2 步的调用也不离开企业网络，整个过程的数据全部留在企业环境中。

## 代码执行沙箱

Agent 在制作文件、计算、绘图时需要实际运行代码。这些代码在独立的沙箱容器中执行，与应用服务完全隔离：

- **一次性容器**：每次回复使用独立的工作区，执行结束后环境清空，不同任务之间互不影响。
- **最小权限**：容器以非 root 用户运行，技能目录只读，限制 CPU 和内存用量，使用专用网络。
- **成果统一收集**：只有写入交付区的文件会被收集到对象存储并交给员工，中间文件随容器销毁。
- **预装运行环境**：文档制作所需的软件包和中文字体预先安装在沙箱镜像中，无需联网安装。

## 凭据与数据安全

- **凭据集中保管**：模型密钥、第三方服务密钥由平台加密保存，不下发到员工电脑，员工也看不到。
- **工具调用有防护**：工具执行设置超时和输出长度上限，异常不会把内部错误信息暴露给模型和员工。
- **账号安全**：密码使用业界标准的哈希算法存储，登录使用令牌认证。

## 部署规格建议

| 规模 | 建议配置 | 说明 |
| --- | --- | --- |
| 试点（一个部门，几十人） | 单台 4 核 8G 服务器，100G 磁盘 | 全部组件部署在同一台机器，使用云端模型服务 |
| 推广（多个部门，数百人） | 应用与沙箱分开部署，数据库独立 | 文档制作类任务占用资源较多，沙箱单独扩容 |
| 本地模型 | 另配 GPU 服务器部署开源模型 | 对数据不出企业有严格要求时采用 |

实际配置取决于并发人数、知识库规模和是否部署本地模型，上线前按试点期的实际用量评估。

## 上线检查清单

- [ ] 模型供应商已接入并通过连通性验证，对话、向量、重排序模型按需配置
- [ ] 对象存储已配置，文件上传、下载和产出物收集正常
- [ ] 沙箱服务可用，文档制作任务能生成并交付文件
- [ ] 后台任务服务运行正常，文档解析和建立索引能够完成
- [ ] 各部门知识库已建好，资料维护者账号已分配
- [ ] 公共 Agent 已创建、绑定知识库并启用，员工侧可见
- [ ] 用量限额已按预算设置
- [ ] 服务器防火墙只开放必要端口，管理后台访问受控
- [ ] 数据库和对象存储的备份策略已落实

## 运维与成本控制

- **用量限额**：可按场景或用户限制调用次数，控制模型成本。
- **消耗可查**：每次回复按 Supervisor 和各成员分别记录模型消耗。
- **长对话自动压缩**：对话过长时自动将较早的内容整理成摘要，控制每次调用的输入长度。
